gRPC definitions (BLUEPRINT §3.3, §4.1). Packages are versioned (`neuroforge.<area>.v<N>`); a breaking change
creates `v2` next to `v1` (BLUEPRINT §4.3).

| File | Service | Step |
|---|---|---|
| `ingest/v1/ingest.proto` | `IngestService`: `StreamChunks` (client-stream), `GetStreamState`, `FinishStream` | 2.7 |

Rules that hold for every file here (SECURITY-REQUIREMENTS §G):

- **Device → platform only (SEC-090).** No operation, message or field sends commands, parameters, waveforms or
  triggers to acquisition or stimulation hardware. `node tools/hw-guard/cli.mjs` scans this directory in CI.
- **No timing guarantee (SEC-093).** Acknowledgements only report what is durably stored.
- **Timestamps are never rewritten (SEC-094).** The original LSL timestamps, clock-offset series and local
  monotonic-clock samples are stored as sent.

Generated code: the Python server and the edge prototype use stubs generated by `grpcio-tools` and committed under
`services/platform/nf_platform/ingest/stream/_proto/` (regenerate with
`.venv/Scripts/python -m nf_platform.ingest.stream.gen`; a test fails when the committed stubs drift from the
`.proto`). Committing them keeps the server free of a build step and of a runtime dependency on `grpcio-tools`
(protoc). nf-core (Rust, step 4.2) generates its own code from the same file.
