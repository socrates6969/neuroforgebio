# WCAG 2.2 AA audit — T12: keyboard + screen-reader pass, /interface and /playground

Scope (web-queen T12): `/interface` and `/playground`, both themes, focused on focus order, the
`aria-live` announcements (including the new singular "unit" case), and reduced motion, against the
current per-theme-stills / no-WebGL-fallback code.

Method: read `apps/web/src/pages/interface.astro`, `apps/web/src/pages/playground.astro`, and both
scripts (`apps/web/src/scripts/interface.ts`, `apps/web/src/scripts/interface-scene.ts`,
`apps/web/src/scripts/playground.ts`) in full, plus the content each reads its labels from. Where a
finding depends on real data (is a plural-mismatch actually reachable, or only theoretical?), I
computed it from the committed asset (`apps/web/src/assets/playground/mc-rtt-playground.json`)
rather than guessing.

## Findings

| # | Issue | Page(s) | Severity | Status |
|---|---|---|---|---|
| 1 | `unitsWord`/`neuronsUnit` were fixed, always-plural strings ("units", "neurons"), so both the visible electrode-select `<option>` text and the `aria-live` announcement read "1 units" whenever a selection has exactly one unit. On `/interface` this wasn't an edge case: **46 of the 82 electrodes with any units have exactly one** (computed from the committed asset), so a majority of electrode selections — both the dropdown text sighted users read and the screen-reader announcement on selecting one — said "1 units". On `/playground` the equivalent (`neuronsUnit`, "neurons") is currently unreachable: `neuronCounts` is `[8, 16, 32, 64, 130]`, never 1, so it's the same pattern but dormant, not live. | `/interface` (was live, majority of interactions), `/playground` (dormant) | Moderate (interface) / Low (playground) | **Fixed on `/interface`, verified** — re-checked against `origin/web/integration` `41a3a00` (`fix/interface-unit-word` `95ba8fd`): a new `unitWord: "unit"` content field, `units.length === 1 ? unitWord : unitsWord` at both call sites (`interface.astro` line 131, `interface.ts` line 335), and a dist test (`apps/web/test/interface.test.mjs`, `dist: electrode options use "unit" for exactly one unit, never "1 units"`) asserting the count of `" 1 unit"` options matches the asset's actual single-unit electrodes — 46, matching what I computed independently. `/playground`'s `neuronsUnit` stays a dormant note (nfb-playground: intentionally not adding an unused singular string while it's unreachable) |
| 2 | Clicking "Show anyway" (the reduced-motion opt-in on `/interface`) hid its own container (`box.hidden = true`) without moving focus anywhere. Neither script called `.focus()` at all. Hiding a focused element resets focus to `<body>` by default in every browser, so a keyboard user who clicked that button lost their place and had to tab from the top of the page again to reach the stage or controls it just revealed, instead of landing on them directly. | `/interface` | Moderate | **Fixed, verified** — `fix/interface-optin-focus` `7f8e577`: the click handler now sets `stage.tabIndex = -1` and calls `stage.focus()` *before* hiding the button's container, so focus never has anywhere to fall back to; the stage becomes the real, `tabIndex = 0` focusable scene once `start()` finishes, or stays focused (with the still image and an error message) if WebGL then fails. Real Playwright coverage, not just a static check: `apps/web/e2e/interface.spec.ts`'s "reduced motion: still image first, scene on request" now opens the button by keyboard (`focus()` + `Enter`) and asserts `[data-ix-stage]` is focused both immediately after and once the scene has started — covering the exact failure mode (focus surviving the async gap while the scene loads), which a source read alone couldn't confirm. |

Everything else checked out clean:

- **Focus order**: DOM order matches visual/reading order on both pages — status messages, then
  the stage, then the controls form (play/tour/reset/zoom, then layer checkboxes, then the
  electrode select), then the inspector. `/interface`'s stage is correctly *not* focusable
  (`role="img"`, no `tabindex`) until the live scene actually starts, at which point the script
  upgrades it to `role="group"`, adds `tabIndex = 0`, `aria-describedby="ix-hint"` (naming the
  orbit-key hint), and a visible `:focus-visible` outline — the static markup never promises
  keyboard operability it can't yet deliver.
- **`aria-live`**: both pages use exactly one hidden `aria-live="polite"` region each
  (`data-ix-live` / `data-pg-live`); every other dynamic `<output>`/readout is explicitly
  `aria-live="off"` so nothing double-announces — the correct pattern (the one `/arena` originally
  got wrong, already fixed under T4/T11). `/playground`'s announcement is debounced 400ms after the
  user stops adjusting a control ("one polite announcement... not one per slider step"); `/interface`'s
  tour captions announce once per step, not per frame. Neither page announces on every animation
  frame.
- **Reduced motion**: `/interface` gates the entire WebGL scene behind
  `matchMedia('(prefers-reduced-motion: reduce)')` — reduced motion (and no-WebGL) show a static
  still image plus an explicit opt-in, never autoplay. `/playground`'s 2D canvas replay only ever
  plays when the visitor presses Play; it tracks the same media query and (per the existing,
  already-tested behaviour) never autoplays and stops if reduced motion is switched on mid-playback.
- **Per-theme stills / no-WebGL fallback**: `stillClinical`/`stillCosmos` are selected once from
  `THEME` at build time (no client-side theme detection to get wrong); the `<noscript>` `<Picture>`
  and the script-inserted `<picture>` (AVIF + JPEG fallback) use the identical `alt` text either
  path, so a screen-reader user gets the same description whether or not JS ran.

Also worth noting: nfb-playground closed out `/playground`'s dormant singular-"neurons" case (part
of finding #1) with a tripwire rather than an unused string — `apps/web/test/playground.test.mjs`,
`asset: neuron counts never equal 1, so the plural "neurons" is always right` — so if a future asset
update ever adds a count of 1, the test fails loudly instead of silently shipping "1 neurons".

## Files changed
None on my side, on either branch. Both findings were in files `nfb-playground` owns
(`apps/web/src/pages/interface.astro`, `apps/web/src/scripts/interface.ts`, `apps/web/e2e/interface.spec.ts`,
`apps/web/test/playground.test.mjs`, and the `unitsWord`/`neuronsUnit`/`unitWord` content fields) —
reported to them directly with the exact fix location, and both are now fixed and verified (real
Playwright/dist coverage, not just re-read source) at `95ba8fd` (#1) and `7f8e577` (#2).
