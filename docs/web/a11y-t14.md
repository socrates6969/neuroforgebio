## What each test checks

1. **`${theme}: exactly one h1 per page, no heading-level skips`** — extracts every `<h1>`–`<h6>`
   in document order (from `<body>`, `<head>` stripped) for every built page in both themes, and
   asserts exactly one `<h1>` and no adjacent level jump greater than 1 (the same adjacent-pair
   heuristic most a11y linters use, e.g. axe's `heading-order` rule). `/gallery` is excluded from
   both parts — it renders every `@nf/ui` component in isolation as a demo (its own `<h1>` plus
   each demo's own, e.g. `Hero`'s), which `apps/web/test/html.test.mjs` already exempts by name
   from the one-`<h1>` rule for the same reason; a demo page isn't a real document outline, so
   skip-checking it isn't meaningful either.
2. **`${theme}: every form control has an accessible label`** — runs `_dist.mjs`'s existing
   `unnamedControls()` (already used per-page in `interface.test.mjs`/`playground.test.mjs`) over
   every built page, not just those two.
3. **`${theme}: every <a> has non-empty accessible text`** — new `unnamedLinks()` helper (kept
   local to this file rather than added to the shared `_dist.mjs`, to keep the footprint small):
   flags an `<a>` with no visible text, no `aria-label`/`aria-labelledby`, and (for an image-only
   link) no `alt` on a contained `<img>`. `aria-hidden="true"` links are skipped — intentionally
   removed from the accessibility tree, not a labelling bug.
