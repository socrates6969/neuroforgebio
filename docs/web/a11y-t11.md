# WCAG 2.2 AA audit — T11: /docs/* and /arena

Scope (web-queen T11): every `/docs/*` page (`/docs`, `/docs/api`, `/docs/changelog`, the 4
quickstarts, `/docs/python-sdk`, `/docs/c-abi`) and `/arena`, both themes. Criteria: heading order,
landmark names, code-block focus/scroll (2.1.1 Keyboard; 1.4.10 Reflow at 320px), link purpose
(2.4.4), contrast of code tokens, target size (2.5.8, new in 2.2).

Method: read every page/component source plus the shared `DocsShell`/`DocSections` they all render
through (so a finding there covers every `/docs/*` page at once), and the current `arena/index.astro`
+ its `<style>`. No build/run needed for this pass (static reasoning); the one place I flagged a
pixel-threshold judgement call (target size) I said so rather than asserting a firm number I can't
verify without real-browser measurement.

## Findings

| # | Issue | Page(s) | Criterion | Severity | Status |
|---|---|---|---|---|---|
| 1 | `/arena`'s leaderboard table (`.arena-board`, `min-width: 560px`) sits in `.arena-board-wrap` (`overflow-x: auto`), which is a grid item of `.arena { display: grid }` with no `min-width: 0` override — the same CSS Grid "blowout" pattern as the `/gallery` finding in `docs/hive/A11Y-AUDIT.md`. Unlike that one, this doesn't depend on font metrics: 560px is an explicit, theme-independent minimum, well over both 320px and 360px viewports, so once it renders this *will* overflow, not just risk it. | `/arena` | 1.4.10 Reflow | Moderate | **Reported, not fixed** — `apps/web/src/pages/arena/index.astro` is nfb-arena's file |
| 2 | `DocsShell.astro`'s side-nav links (`.side a`) had no padding or `min-height`; at 15px font-size the raw target height is close to (possibly under, possibly over — genuinely can't tell without a real render) the 24×24px minimum of 2.5.8 Target Size. The 6px list gap might satisfy the Spacing exception even if the target itself is under 24px, but rather than resolve that judgement call I just fixed it outright — cheap, unambiguous, and it also enlarges the clickable area to the link's full width, not just the glyphs. | Every `/docs/*` page | 2.5.8 Target Size (AA, new in 2.2) | Low | **Fixed** |

Everything else checked out clean:

- **Heading order**: every `/docs/*` page is h1 (`DocsShell`) → h2 (`DocSections`/page-specific
  sections) → h3 (items), no skips, no duplicate h1. `[guide].astro`'s endpoints table adds one more
  h2, correctly sequenced after `DocSections`' own h2s. `/arena` is h1 (`SectionHead`) → h2 (the
  visually-hidden "Decoder settings" form legend, "Your runs", and — in the unavailable state —
  "Decoder loading unavailable" / "Evaluate your own decoder privately"), never deeper, so nothing to
  skip.
- **Landmark names**: `DocsShell`'s side `<nav aria-label={nav.label}>` ("Documentation") is
  distinct from `Base.astro`'s primary nav ("Primary") and footer nav ("Footer") — no collision.
  `/arena`'s `<form aria-labelledby="h-arena-controls">` is a form landmark named "Decoder settings"
  (from its own visually-hidden h2), also distinct.
- **Code-block focus/scroll (2.1.1)**: `DocSections`' `<pre class="code" tabindex="0" aria-label=...>`
  and `[guide].astro`'s endpoints table (`<div class="scroll" tabindex="0" role="region"
  aria-label=...>`) are both keyboard-focusable, scrollable, and named — already the established,
  correct pattern from the main audit. `/arena` has no code blocks (it's a form + table interface).
- **Reflow at 320px, everything else**: `DocsShell`'s two-column grid (`grid-template-columns: 220px
  minmax(0, 1fr)`) switches to a single column at ≤860px (well before 320px), and its content column
  already has `min-width: 0` set — no blowout risk there. `/arena`'s form controls
  (`.row { flex-wrap: wrap }`) wrap correctly; the only real 1.4.10 risk is finding #1.
- **Link purpose (2.4.4)**: every link on both `/docs/*` and `/arena` — side-nav items, quickstart
  list, the API-reference-table method+path links, the CC-BY dataset/DOI/licence links — carries its
  own descriptive, distinguishable text; none rely on surrounding context ("click here" etc.).
- **Contrast of code tokens**: neither `/docs/*` nor `/arena` has a syntax highlighter (deliberately
  — inline styles would violate the CSP, per `DocSections`' own header comment), so code text is
  plain `--color-ink` on `--color-surface`, already covered by
  `packages/themes/test/contrast.test.mjs`'s generic ink-on-surface pairs in both themes. No
  separate "code token" palette exists to audit.
- **Target size, elsewhere**: `/arena`'s radios (28px), selects/number inputs (36px) and the primary
  button are all comfortably over 24px. `docs/api.astro`'s `<details><summary>` toggles have no
  explicit sizing either, same category as finding #2 but out of this pass's file ownership
  boundary (`docs/api.astro`'s `<style is:global>` already belongs to a page I've edited before for
  other reasons; flagging here rather than bundling an unrelated style change into this branch —
  happy to take it as a follow-up if wanted).
