# WCAG 2.2 AA audit — T13: /investors and /pricing

Scope (web-queen T13): `/investors` and `/pricing`, both themes and both locales where built
(`/no/pricing`; `/investors` has no NO route). Heading order, table semantics for evidence rows,
link purpose for source links, the `EarlyAccessForm` labels/errors on `/pricing` including the
`/no/pricing` `earlyAccessNote` path, and 320px reflow.

Method: read `apps/web/src/pages/investors.astro`, `apps/web/src/pages/[page].astro` (pricing's
route), `apps/web/src/pages/no/[page].astro` (the `/no/pricing` path, built in T10), the shared
`apps/web/src/components/PageBody.astro`, `apps/web/src/components/Evidence.astro`, and
`packages/ui/src/components/EarlyAccessForm.astro`, plus both pages' content JSON
(`packages/content/content/pages/investors.json`, `pricing.json`). Both pages render entirely
through components already covered in depth by earlier passes (main audit, T5, T10); this pass
checked whether *these two pages specifically* trigger anything those components' general
correctness doesn't already guarantee.

## Findings

None. Both pages are clean against every criterion in scope.

- **Heading order**: both use `PageBody.astro` — h1 (`SectionHead level={1}`) → h2 per section → h3
  per item, no skips. `/pricing`'s early-access section is a single `<h2 id="h-early-access">`
  (PageBody's own section heading); `EarlyAccessForm` is called with `labelledBy="h-early-access"`
  (`[page].astro`, since `pricing.json` already has an `"early-access"` section), so it correctly
  suppresses its own `<h2 id="ea-h">` rather than emitting a second, redundant heading for the same
  content.
- **Table semantics for evidence rows**: `/investors`' five sections with an `evidence` array (16
  claims total) render through `Evidence.astro` as an `<ol>` — each `<li>` pairs one claim's text
  with its source/grade. This is the correct choice, not a gap: it's not tabular/grid data (no
  shared columns being compared across rows), so list semantics are more accurate than a `<table>`
  would be. `/pricing` has no evidence entries.
- **Link purpose for source links**: `/investors`' 16 evidence entries all cite an internal repo
  path (e.g. `market/regulation.md §1`) with no `sourceUrl`, so `Evidence.astro` renders them as
  plain text, not links (`{c.sourceUrl ? <a>... : <span>...}`) — nothing to check for link purpose
  there. The page's three CTA links (`Open the playground`, `Decoder Arena (in development)`,
  `Law tracker`) are each distinct and descriptive out of context. `/pricing` has no source links.
- **`EarlyAccessForm` labels/errors**: the email input has a real `<label for="ea-email">`; the
  whole `<fieldset>` is `disabled` and the form has no `action` and no script anywhere in the
  codebase that could submit it — "errors" don't apply because there is no submittable state yet
  (BUILD-GUIDE 4.7's intentional design, already verified in the main audit). The disabled-state
  explanation (`disabledNote`) is wired via `aria-describedby="ea-note"` on the `<form>`, so a
  screen-reader user gets it once, at the form level, not repeated per control.
- **`/no/pricing`'s `earlyAccessNote` path**: unchanged since T10 (`apps/web/src/pages/no/[page].astro`,
  mine) — the form is fully omitted on `/no/pricing`; the note (text + a link to the English form,
  `hreflang="en"`, no `lang` override since the link text itself is Norwegian) renders in the same
  `"early-access"` section via `PageBody`'s per-section slot, already dist-verified correct.
- **320px reflow**: neither page has anything that could reproduce the `/gallery`/`/arena` CSS Grid
  "blowout" pattern from earlier findings. `PageBody`'s two-column grid switches to a single column
  at ≤800px (well above 320px) and its content column already has `min-width: 0`;
  `EarlyAccessForm`'s `input { flex: 1 1 220px; min-width: 0 }` inside a `flex-wrap: wrap` row is
  already correctly guarded the same way. Long CTA button labels and item body text wrap normally
  (no `white-space: nowrap` anywhere in either page's path).
