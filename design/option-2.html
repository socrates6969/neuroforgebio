platform

One pipeline. Electrode to model.

Four composable stages you can run in the cloud, at the edge, or from a notebook. Every run is versioned, so results stay reproducible.

  1. 1
    $ nf ingest lsl://headset-01 ✓

    Ingest

    Hardware-agnostic connectors for EEG, ECoG, and microelectrode arrays. BIDS, Lab Streaming Layer (LSL), EDF/BDF, NWB, XDF — into low-latency time-series storage.

    EEGECoGmicroelectrodeBIDSLSL
  2. 2
    $ nf clean --pipeline ica-default ✓

    Clean

    Automated neuro-cleaning: filtering, ICA, artifact rejection, re-referencing, normalization. Versioned, reproducible pipelines with provenance attached to every output.

    filterICAartifact rejectionre-refprovenance
  3. 3
    $ nf models get motor-intent/v1 ✓

    Neuro-AI

    Model marketplace: motor-intent decoding, cognitive-state estimation, plus bring-your-own-model. Benchmarks published with methods, on public datasets.

    motor intentcognitive stateBYO model

    $ nf sdk add python cpp unity ✓

    SDKs

    Python, C++, Unity / Unreal. Stream in, get predictions out — with the same pipeline definition everywhere.

    PythonC++UnityUnreal
import neuroforge as nf

stream = nf.connect("lsl://headset-01")
clean  = stream.pipeline("ica-default").run()
intent = nf.models.get("motor-intent/v1").predict(clean)

for window in intent:
    print(window.label, window.confidence)
#include <neuroforge/neuroforge.hpp>

int main() {
    auto stream = nf::connect("lsl://headset-01");
    auto clean  = stream.pipeline("ica-default").run();
    auto model  = nf::models::get("motor-intent/v1");

    for (const auto& w : model.predict(clean)) {
        std::cout << w.label << " " << w.confidence << "\n";
    }
}
using NeuroForge;
using UnityEngine;

public class IntentDriver : MonoBehaviour {
    NfStream stream; NfModel model;

    void Start() {
        stream = Nf.Connect("lsl://headset-01").Pipeline("ica-default");
        model  = Nf.Models.Get("motor-intent/v1");
    }
    void Update() {
        var w = model.Predict(stream.Latest());
        if (w.Label == "left") transform.Rotate(0, -1, 0);
    }
}

security & compliance

Neural data is sensitive. We treat it that way.

Security is part of the platform config, not an add-on. Status labels below are honest: some controls are planned or on the roadmap.

security.yamlread-only
encryption:
  at_rest: AES-256
  in_transit: TLS 1.3
access:
  rbac: true
  audit_log: true
hipaa:
  workflows: aligned
  baa: planned        # enterprise
soc2_type_ii: roadmap
neural_data_privacy:
  us_state_laws: [CO, CA, CT, MT]
data_residency: planned
deidentification: tooling
  • BUILT-IN
    AES-256 at rest, TLS 1.3 in transitEncryption on by default for every stream and file.
  • BUILT-IN
    RBAC & audit logsRole-based access down to the dataset, with a full access trail.
  • DESIGN
    HIPAA-aligned workflowsDesigned for HIPAA-aligned workflows; BAA available for enterprise (planned).
  • ROADMAP
    SOC 2 Type IIOn the roadmap. Not certified today.
  • DESIGN
    Neural-data privacy lawsBuilt to support emerging US state neural-data privacy laws (e.g. Colorado, California, Connecticut, Montana).
  • PLANNED
    Data residency & de-identificationRegional storage options (planned) and de-identification tooling.

Nothing on this page is legal advice. Research and development use only.
