Editorial

Picks and shovels for neurotech.

Every BCI team rebuilds the same plumbing. We think that plumbing should be shared, versioned and citable.

Neural recordings arrive in a dozen formats, from a dozen devices, at sampling rates that punish naive storage. Before a single decoder is trained, most teams spend months writing converters, filters and artifact heuristics that live in one student's notebook and die with their graduation.

“Your team should ship decoders, not data pipelines.”

NeuroForge is a hardware-agnostic data layer for electroencephalography, electrocorticography and microelectrode arrays. It ingests streams and files through open standards, cleans them with transparent, versioned pipelines, and hands the result to models — ours, the community’s, or yours.

We are building for two readers at once: the laboratory that needs reproducibility and a free tier, and the seed-stage hardware company that needs a production data stack and a compliance story before its first enterprise pilot. The platform is intended for research and development use.

This page is a design concept. Where it shows numbers in interface mock-ups, they are demo data or targets, and are labelled as such.

Methods

From electrode to model, in four sections.

Each stage is a documented, versioned step with provenance — the kind of pipeline you can describe in a methods section and a reviewer can reproduce.

§1Ingest

Ingest

Hardware-agnostic connectors for EEG, ECoG and microelectrode arrays, backed by low-latency time-series storage built for high channel counts and long sessions.

  • BIDS
  • Lab Streaming Layer
  • EDF/BDF
  • NWB
  • XDF
Marginalia. Open standards first: a recording that enters as BIDS can always leave as BIDS. No proprietary lock-in on your raw data.
§2Clean

Clean

Automated neuro-cleaning: filtering, independent component analysis (ICA), artifact rejection, re-referencing and normalization. Every run is versioned and reproducible, with full provenance attached to the output.

  • band-pass / notch
  • ICA
  • artifact rejection
  • re-reference
  • normalize
Marginalia. Pipelines are data, not scripts: parameters, library versions and input hashes are stored with each result.
§3Neuro-AI

Neuro-AI model marketplace

Models for motor-intent decoding and cognitive-state estimation, plus bring-your-own-model hosting. Benchmarks are published with methods, on public datasets.

  • motor intent
  • cognitive state
  • bring your own
Marginalia. No leaderboard without a methods section: each benchmark ships with its dataset, split and evaluation code.
§4SDKs

SDKs

Python, C++, Unity and Unreal. Stream in, get predictions out — from a notebook, an embedded device, or a game engine running an experiment.

  • Python
  • C++
  • Unity
  • Unreal
Marginalia. The same API surface across languages, so a prototype in Python becomes a C++ build without a rewrite of the data model.

Compliance & security

Data Availability & Ethics Statement

Neural data is among the most personal data there is. The platform is designed around that fact. Status is stated plainly for each item.

Encryption
AES-256 at rest, TLS 1.3 in transit design baseline
Access control
Role-based access control and audit logs design baseline
Health data
Designed for HIPAA-aligned workflows; BAA for enterprise planned
De-identification
De-identification tooling for recordings and metadata design baseline
Attestation
SOC 2 Type II roadmap
Neural-data privacy
Built to support emerging US state neural-data privacy laws (e.g. Colorado, California, Connecticut, Montana)
Data residency
Regional data residency options planned
Intended use
Research and development. Not a medical device; no diagnostic or therapeutic claims.
